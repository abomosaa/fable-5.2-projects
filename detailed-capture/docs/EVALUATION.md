# Evaluation

All numbers in this file are generated by `eval/make_report.py` from `eval/results/summary.json`, which is written by `eval/run_all.py` (synthetic) and `eval/run_real.py` (real photographs). Both drive the **same core commands the Android app calls** (`frame.add`, `register`, `coverage`, `compose`, `export.flat`) through the `dcap` CLI; scoring is done by `eval/evaluate.py`, an independent Python/OpenCV implementation that never sees the core's internals.

Reproduce: `scripts/fetch_deps.sh && scripts/build_opencv_host.sh && cmake -S core -B build/core -G Ninja && cmake --build build/core && python eval/gen_synthetic.py datasets/synthetic/sets && python eval/run_all.py && python eval/run_real.py && python eval/make_report.py`

Host used for the numbers below: Intel(R) Core(TM) i7-14700K, 28 logical CPUs, Linux; the core ran with **4 worker threads**.

## 1. What is measured

* **Synthetic sets** are rendered by `eval/gen_synthetic.py` from a known high-resolution source with a pinhole camera at random 3-D poses (position, pan/tilt ±5°, roll ±4°, distance ±5 %), optical blur + pixel-aperture integration (3× super-sampling), exposure ±12 %, white balance ±4 %, vignetting, sensor noise, 4:2:0 JPEG, and mixed EXIF orientations. The pipeline never sees poses. Overview and close-ups are 1600×1200 px.
* **Registration error** compares every accepted frame's estimated transform with the true pose on a 9×7 grid, expressed in output pixels (absolute, relative to the true overview pose) and between overlapping frame pairs (relative — what causes seams and ghosting).
* **Reconstruction quality** uses matched 768×768 windows: fused result vs. the pristine source re-sampled onto the output grid, and the same for the overview enlarged (bicubic) to identical dimensions. A per-channel gain/offset fit removes exposure differences for both. `f50` is the spatial frequency (cycles per output pixel) up to which the image stays coherent (magnitude-squared coherence ≥ 0.5) with the reference; sharpening or invented texture cannot raise it. `HF-corr` is the correlation of the detail band (image minus Gaussian σ=1.5).
* **Real sets** have no ground truth. One close-up is withheld from the pipeline and used as an independent high-resolution reference for the area it covers (leave-one-out); it is located on the result by a separate OpenCV-Python SIFT+MAGSAC registration.

## 6. Deterministic tests

| test | covers |
|---|---|
| transform_composition | homography algebra, pixel-centre convention, radial model inverse, frame model round trip, validation of mirrored/folded/stretched transforms, edit transforms (4 quarter turns = identity, integral crops, inscribed rotation) |
| exif_orientation | all 8 EXIF orientations (both byte orders): metadata, decoded pixels, continuous transform vs. raster permutation, exact 1/r reduced decoding |
| registration_outliers | 45 % gross outliers, pure outliers, collinear (degenerate) and mirrored configurations, global refinement recovering perturbed transforms |
| end_to_end_coverage_provenance | full pipeline on rendered views: registration error, coverage follows accepted footprints (exclude/undo), per-tile provenance sums to 1, source inspection, detail statistics, fused closer to truth than enlarged overview |

| tile_boundaries | 512 vs 1024 block layouts give identical pixels; pyramid levels are exact 2×2 averages across tile borders |
| cancel_restart_resume | cancel mid-render keeps the previous result; journal; resume after dropping caches is bit-identical to an uninterrupted run; incremental block reuse; interrupted-job detection |
| persistence_undo | undo/redo of edits and frame removal, byte-identical reload, originals untouched, damaged project file reported, invalid inputs refused |
| export_formats_edits | PNG/TIFF/BigTIFF lossless equality, streaming JPEG, exact rotation/crop, colour edit maths, scaled export, DZI package + viewer, JPEG size limit, odd sizes, ICC pass-through, measurement with/without reference |

## 8. Limits of this evaluation

* Synthetic frames are rendered, not photographed; they model geometry, sampling, blur, noise, exposure and JPEG, but not rolling shutter, chromatic aberration, focus breathing or real specular reflections.
* Real sets come from four subjects and a handful of cameras. No physical phone was available, so no set was captured with the app's own camera screen (see docs/DEVICE_VERIFICATION.md).
* `f50` and the glyph classifier measure agreement with a reference; they say nothing about colour fidelity.
* The estimated genuine detail is an estimate (sampling × relative sharpness), not a measurement.
